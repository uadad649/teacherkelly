# 성인 영어 챌린지

유튜브 주소 하나를 넣으면 자막을 받아 오고, Claude 가 그것으로
**푸는 시트(HTML)** 를 만들어 메일로 보내 준다.

- **내 PC** 에서는 `.bat` 파일을 눌러서 쓴다. (지금까지 쓰던 방식 그대로)
- **GitHub** 에서는 Actions 탭의 `Run workflow` 버튼으로 쓴다.

## 시트는 어떻게 생겼나

읽고 마는 문서가 아니라 한 장짜리 학습 앱이다. 서버 없이 파일 하나로 돈다.

```
표지  →  1단계 단어      뜻 보고 영어 4지선다
      →  2단계 문장      낱말을 눌러 순서대로 놓기
      →  3단계 빈칸      문장 속 한 곳을 비우고 채워 넣기
      →  연습            쉐도잉 · 받아쓰기 · 말하기 미션
```

낱말 하나 → 통문장 → 문맥 속의 한 자리, 순서대로 좁혀 들어간다.
빈칸의 오답 보기는 Claude 가 `slept` 에 대해 `sleep / sleeping / sleeps` 처럼
**실제로 헷갈리는 것**으로 만든다. 그 재료가 없는 시트(예전에 만든 것)에서는
예문에서 핵심 낱말을 자동으로 골라 비운다.

- 한 화면에 한 문제. 위에는 진행바와 정답·오답 수가 늘 붙어 있다.
- 문항마다 바로 채점하고, **틀렸을 때만** 왜 그런지 한 줄이 더 붙는다.
- 한 단계가 끝나면 정답률을 네 구간(100 / 80 / 50 / 그 미만)으로 보여 준다.
- **틀린 문제만 다시 나온다.** 그것을 다 맞혀야 다음 단계가 열린다.
- 문제마다 영상의 그 지점으로 넘어가고, 답은 눌러서 발음을 들을 수 있다.
- 푼 기록·받아쓰기·쉐도잉 횟수는 그 브라우저에 저장된다. 다시 열면 이어서 푼다.

메일 **본문**에는 읽기용 요약이 들어간다. 지메일은 자바스크립트를 지우고
CSS 변수·grid 를 모르기 때문에 퀴즈 앱이 본문에서는 돌지 않는다.
푸는 것은 **첨부 파일**을 열어서 한다.

### 영상은 왜 어떤 때는 화면 안에서 안 나오나

유튜브는 **파일을 두 번 눌러 연 페이지**(주소가 `file://` 로 시작하는 것)에서
임베드를 거절한다. 리퍼러가 없다는 이유인데, 화면에는
`동영상 플레이어 구성 오류 153` 이 뜬다. 메일 첨부를 내려받아 열면 늘 이 경우다.

그래서 시트는 두 모습을 갖고 있다.

| 어떻게 열었나 | 영상 자리 |
|---|---|
| `시트열기.bat` · `한번에.bat` 등 (`http://127.0.0.1:...`) | **화면 안에서 그대로 재생.** 문제를 넘길 때마다 그 장면으로 이동 |
| 파일을 두 번 눌러서 (`file://`) | 미리보기 그림 + 그 지점부터 유튜브로 넘어가는 단추 |

오류 상자를 그대로 두지는 않는다. 어느 쪽이든 문제 풀이는 그대로 된다.
`.bat` 으로 시트를 만들면 자동으로 `http` 쪽으로 열린다. 검은 창을 닫으면
서버도 같이 끝난다.

## 1. 저장소에 올릴 파일

이 폴더를 통째로 올리면 된다. `.github/workflows/` 경로가 정확해야
GitHub 이 워크플로를 알아본다.

```
main.py                        ← GitHub 이 실행하는 입구
adult_local.py                 ← 실제 내용물 (내 PC 와 공용)
sheet_template.html            ← 시트 모양 (푸는 화면 전부가 여기 있다)
mail_template.html             ← 메일 본문 모양 (읽기용)
requirements.txt               ← 필요한 라이브러리
words.json                     ← 지금까지 배운 표현·단어 (복습에 쓴다)
.github/workflows/daily.yml    ← 이 경로 그대로여야 한다
결과/                          ← 만들어진 시트가 쌓이는 곳
```

`붙여넣기.txt`, `응답.json`, `진행중.json`, `메일본문.html` 은 한 번 돌 때만
쓰고 버리는 중간 파일이라 `.gitignore` 로 빼 두었다. 올리지 않아도 된다.

## 2. Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 필수 | 무엇 |
|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | **필수** | 지금 쓰는 Claude 구독으로 인증. 아래 설명 참고 |
| `GMAIL_USER` | 메일 받으려면 | 보내는 지메일 주소 |
| `GMAIL_APP_PASSWORD` | 메일 받으려면 | 아래 설명 참고 |
| `MAIL_TO` | 선택 | 받을 주소. 없으면 `GMAIL_USER` 로 온다 |
| `ANTHROPIC_API_KEY` | 선택 | API 키로 쓰고 싶을 때만. 있으면 이쪽이 먼저 쓰인다 |
| `WEBSHARE_PROXY_USERNAME` | 선택 | 자막이 계속 막힐 때만 (5번 참고) |
| `WEBSHARE_PROXY_PASSWORD` | 선택 | 〃 |

### Claude 구독 토큰

**Claude Pro 구독에 API 사용권은 들어 있지 않다.** 둘은 완전히 별개 요금이다.
대신 구독을 그대로 쓰는 공식 방법이 있다 — Pro·Max·Team·Enterprise 에서 된다.

내 PC 의 터미널(PowerShell)에서:

```
claude setup-token
```

브라우저가 열리고 승인하면 **1년짜리 토큰**이 터미널에 찍힌다.
이 값을 `CLAUDE_CODE_OAUTH_TOKEN` Secret 에 넣는다.
어디에도 저장되지 않으니 창을 닫기 전에 복사할 것.

이 토큰은 모델에게 묻는 일만 할 수 있다. 내 PC 나 다른 계정 자원에는
접근하지 못한다. 1년 뒤에는 같은 명령으로 새로 만들어 Secret 을 갱신하면 된다.

### 지메일 앱 비밀번호

평소 로그인 비밀번호가 **아니다**. 구글이 SMTP 용으로 따로 만들어 주는
16자리다.

1. 구글 계정 → 보안 → **2단계 인증**을 먼저 켠다 (안 켜면 메뉴가 안 보인다)
2. 같은 화면에서 **앱 비밀번호** → 이름 아무거나 → 만들기
3. 나온 16자리를 `GMAIL_APP_PASSWORD` 에 넣는다

화면에 `abcd efgh ijkl mnop` 처럼 띄어서 나오는데, 띄어쓰기째로 붙여넣어도
코드가 알아서 지운다.

> 구독 토큰으로 돌리면 시트를 만들 때마다 구독 사용량을 쓴다. 추가 요금은 없다.
> 굳이 API 키(`ANTHROPIC_API_KEY`)를 쓰겠다면 쓴 만큼 따로 과금되고,
> 그때는 워크플로에 `ANTHROPIC_MODEL: claude-sonnet-5` 를 넣어 비용을 줄일 수 있다.

## 3. 실행

1. 저장소 **Actions** 탭
2. 왼쪽에서 **영어 시트 만들기** 고르기
3. 오른쪽 **Run workflow** → 유튜브 주소 붙여넣기 → 초록 버튼

2~4분쯤 걸린다. 끝나면

- 등록한 메일로 시트가 온다 (본문에서 읽고, 첨부 파일을 열면 버튼까지 동작)
- `결과/` 폴더에 HTML 과 자막(.srt) 이 커밋된다
- 실행 화면 맨 위에 무슨 영상을 어떤 자막으로 만들었는지 요약이 뜬다

`words.json` 도 함께 커밋된다. 다음 시트의 **"지난 시트 — 아직 입에 붙었나"**
칸이 여기에 기대고 있으니 지우지 말 것.

## 4. 매일 자동으로 돌리고 싶어지면

`.github/workflows/daily.yml` 안의 `schedule:` 세 줄 주석을 풀면 된다.
다만 그때는 **어떤 영상을 볼지** 정해 줘야 한다. 지금은 사람이 주소를
넣어야만 돌게 되어 있다.

가장 간단한 방법은 저장소에 `videos.txt` 를 만들어 주소를 한 줄씩 적어 두고,
`main.py` 의 `find_url()` 이 아직 안 쓴 줄을 하나 집어 오게 고치는 것이다.

## 5. 잘 안 될 때

### `자막을 못 받았습니다` 가 계속 뜬다

가장 흔한 원인은 **유튜브가 GitHub 서버 IP 를 막는 것**이다. 내 PC 에서는
잘 되던 영상이 GitHub 에서만 안 되면 거의 이 경우다. 유튜브는 데이터센터에서
오는 요청을 자동 자막 스크래핑으로 보고 자주 차단한다.

해결책은 프록시를 하나 끼우는 것이다. `youtube-transcript-api` 가 Webshare 를
공식 지원한다.

1. webshare.io 에서 **Residential** 프록시를 산다 (가장 싼 요금제면 충분)
2. 대시보드의 Proxy 사용자명·비밀번호를 `WEBSHARE_PROXY_USERNAME` /
   `WEBSHARE_PROXY_PASSWORD` Secret 으로 등록

Webshare 가 아닌 프록시를 쓴다면 `YT_PROXY_URL` 에
`http://아이디:비번@주소:포트` 형식으로 넣으면 된다.

돈을 들이고 싶지 않다면, 자막이 안 될 때만 내 PC 에서 `한번에.bat` 으로
돌리면 된다. 같은 코드가 그대로 동작한다.

### `인증 정보가 없습니다` / Claude 호출이 실패한다

`CLAUDE_CODE_OAUTH_TOKEN` Secret 의 철자와, 값 앞뒤에 공백이나 줄바꿈이
딸려 들어가지 않았는지 확인한다. 토큰은 1년이 지나면 만료되므로
`claude setup-token` 을 다시 실행해 Secret 을 갱신한다.

### 메일이 안 온다

2단계 인증을 켜지 않은 채 만든 비밀번호이거나, 평소 로그인 비밀번호를 넣은
경우다. 앱 비밀번호를 새로 만들어 다시 등록한다.

### 자막이 아예 없는 영상

음성인식(Whisper)으로 대신 만들 수 있지만 GitHub 에서는 기본으로 꺼 두었다.
모델을 내려받고 영상 길이만큼 CPU 를 써서 실행이 크게 느려지기 때문이다.
켜려면 `requirements.txt` 의 `faster-whisper` 주석을 풀고, 워크플로에
`ALLOW_WHISPER: "1"` 을 넣는다.

## 6. 내 PC 에서 쓰는 법 (그대로다)

```
한번에.bat              자막부터 시트까지 한 번에   (Claude Code 필요)
1단계_자막받기.bat      자막 → 붙여넣기.txt
이어서_시트만들기.bat   붙여넣기.txt → 시트 HTML   (Claude Code 필요)
2단계_시트만들기.bat    응답.json → 시트 HTML      (직접 붙여넣었을 때)
시트열기.bat            이미 만든 시트를 다시 열기
자막만_받기.bat         .srt 파일만
```

**`1단계_자막받기.bat` 은 자막만 받고 멈춘다.** 시트가 안 나온다고 놀랄 것 없다.
그다음은 둘 중 하나다.

- 그냥 맡기려면 → `이어서_시트만들기.bat` (자막을 다시 받지 않고 이어서 간다)
- 직접 붙여넣으려면 → `붙여넣기.txt` 를 Claude 에 넣고, 받은 JSON 을
  `응답.json` 으로 저장한 뒤 `2단계_시트만들기.bat`

처음부터 한 번에 끝내려면 `한번에.bat` 하나만 누르면 된다.

`한번에.bat` 과 `이어서_시트만들기.bat` 은 `ANTHROPIC_API_KEY` 환경변수가
있으면 API 로, 없으면 설치된 Claude Code 로 알아서 돌아간다.

> `.bat` 파일을 편집할 일이 생기면 줄바꿈이 **CRLF** 인지 확인할 것.
> LF 로 저장하면 cmd 가 명령어를 중간부터 잘라 읽어서 이상한 오류가 난다.
> VS Code 는 오른쪽 아래에 표시된다.
